<objective>
The **resume half** of the decision cycle: a client resume run (`RunAgentInput.resume[]`) is validated against the pending-interrupt registry (D-05), then translated and delivered through the existing decision-submission path — `translateResumeToSubmission` (pure, in event-bridge.ts) → `buildDecisionSubmission` → `executeChatTurn` (chat) or `executeHumanTurn` with a new additive `opts?: ChatTurnOpts` seam (task-linked, A6) — so the engine receives the structured decision and its continuation events stream on the resume run. The resume branch runs BEFORE extractUserText and BEFORE the advisory lock (Pitfall 1), and it finalizes the orphaned `waiting_user` execution row that Phase 2's advisory lock turned into a permanent thread wedge (Pitfall 2). A cancelled resume (A4) clears the registry, closes the row, and completes without an engine call. The registry entry clears only after delivery starts, making duplicate resumes fail with INVALID_INTERRUPT (Pitfall 8).

Purpose: CHAT-09 SC2 (approve/reject with payload; run resumes; engine receives the decision via resume[]), RUNR-08 (resume[] consumption is the canonical half of the interrupt contract), VERF-01 (fake-engine resume-cycle contract tests incl. block-while-pending and all-interrupts-must-resolve, D-09).

Planner's discretion recorded (assumption-delta, advisory): a `resolved` resume whose payload lacks answers → RUN_ERROR with a NEW code `INVALID_PAYLOAD` (research Pattern 2 only sketched id validation; translateResumeToSubmission returns null for missing answers — the distinct code is clearer for Phase 5 debugging). Execution-row finalize statuses per research: resolved → `completed`, cancelled → `cancelled`.

Output: the resume branch in the agent, the pure translation helper, the A6 executor seam, the mock-engine Phase B script, and their contract tests.
</objective>
